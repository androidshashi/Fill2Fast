# Fill2Fast

Repository: https://github.com/androidshashi/Fill2Fast

Chrome Web Store: https://chromewebstore.google.com/detail/fill2fast/ifgdombmnmbenmmecbbfolnhnmccflfd

A local-first Chrome extension that fills job applications from a profile you save once.

> Save your information once → open any job application → review the detected fields → fill them with one click.

- **Local only.** The profile and resume live in `chrome.storage.local`. There is no backend, no account, no telemetry, and the extension pages' CSP blocks all network connections (`connect-src 'none'`).
- **Deterministic.** Fields are classified with configurable keyword rules and confidence scores. No AI.
- **You confirm every fill.** Nothing is filled until you click **Fill Selected**. Uncertain fields are never pre-selected, and existing page values are never overwritten unless you select them.

## 2. Installation

To just use the extension, install it from the [Chrome Web Store](https://chromewebstore.google.com/detail/fill2fast/ifgdombmnmbenmmecbbfolnhnmccflfd). To build it from source:

Requirements: Node.js 20+ and Chrome 116+.

```bash
git clone https://github.com/androidshashi/Fill2Fast.git
cd Fill2Fast
npm install
```

## 3. Build

```bash
npm run build        # typecheck + build into dist/
npm run build:fast   # build without typechecking
```

The build runs in two steps. Vite builds the popup, options page and service worker. A second Vite config builds `content.js` as a single IIFE, because content scripts can't be ES modules.

## 4. Load in Chrome

1. Run `npm run build`.
2. Open `chrome://extensions`.
3. Turn on **Developer mode** (top right).
4. Click **Load unpacked** and select the `dist/` folder.
5. The profile editor opens automatically. Fill in your profile and click **Save profile**.
6. Pin Fill2Fast from the puzzle-piece menu, open a job application, and click the Fill2Fast icon.

After rebuilding, click the reload icon on the Fill2Fast card in `chrome://extensions`, then refresh any open application tabs.

### Permissions

| Permission | Why |
| --- | --- |
| `storage` | Save your profile, settings and resume locally. |
| `activeTab` + `scripting` | Inject the field detector into the current tab **only when you click the icon**. Fill2Fast does not run on pages you haven't opened it on. |
| `optional_host_permissions` | Requested per site, and only when the form is embedded from another domain (for example a Greenhouse iframe on a company careers page). The popup shows **Allow Fill2Fast on this form** and asks for that single origin. |

## 5. Supported fields

| Group | Field types |
| --- | --- |
| Personal | First name, last name, full name, email, phone, city (incl. "Location"), state, country, postal code |
| Professional | Current company, current title, total experience, relevant experience, notice period |
| Skills | Skills (primary + secondary, comma-separated) |
| Links | LinkedIn, GitHub, portfolio/website, Twitter/X, LeetCode |
| Education | Degree, university, graduation year |
| Yes/No questions | Work authorization, visa sponsorship, relocation (select, radio group or checkbox) |
| Salary | Expected and current salary. Detected, but **filled only if you turn on "Allow Fill2Fast to fill salary fields"** |
| Files | Resume/CV upload |

Supported controls: text-like `<input>` (text, email, tel, url, number, search), `<textarea>`, single `<select>`, radio groups, checkboxes, and file inputs. It works with React, Angular and Vue forms because values go through the native setters, followed by `input`, `change` and `blur` events. Open shadow roots and iframes are scanned too.

**Classification signals**, from strongest to weakest: `autocomplete` → `type` → `name` → `id` → `<label>` / `aria-labelledby` → `aria-label` → `data-*` automation attributes → `placeholder` → nearby text. Each signal is scored by its weight and by how much of the text the keywords cover. Agreeing signals add a bonus, and two conflicting interpretations reduce confidence. Anything below 60 is **Unknown** and is never filled.

**Adding a field:** add a rule to `src/core/field-rules.ts`, a value getter to `src/core/profile-values.ts` and, if it needs a new profile property, a default in `src/core/profile-defaults.ts`. Stored profiles automatically pick up the new defaults.

## 6. Known limitations

- **Custom dropdowns and comboboxes** (React Select, Workday's button-based pickers, typeahead location fields with `role="combobox"`) are skipped. They aren't native controls, and typing into them doesn't commit a choice.
- **Resume upload** is attached through a `DataTransfer`, which works for standard `<input type="file">` fields. Sites that accept files only through drag-and-drop, or that upload through their own widget, may ignore it. Fill2Fast then reports "Could not attach resume" and a **Select resume file** button highlights the upload field so you can pick the file yourself. The resume is limited to 4 MB.
- **Embedded forms from another domain** need a one-time grant per origin. Chrome may close the popup while it shows the permission prompt, in which case reopen Fill2Fast.
- **Multi-step forms** are scanned when you open the popup, and fields added while it's open are picked up automatically. Fields that were hidden and then shown by CSS alone are picked up the next time you open the popup.
- **Closed shadow roots** and cross-origin frames you haven't granted can't be read.
- **Free-text questions** ("Why do you want to work here?") are intentionally left alone.
- Yes/No answers are single global answers. Country-specific answers (for example authorized in India but not in the US) aren't modelled yet.
- The **number of years** in range selects ("3-5 years") is matched only when exactly one option contains your value.

## 7. Testing

```bash
npm test             # run all unit + DOM tests once
npm run test:watch   # watch mode
npm run typecheck
```

What's covered (`tests/`):

| File | Covers |
| --- | --- |
| `field-mapper.test.ts` | Classification of `firstName`, `first_name`, `given_name`, `fname`, `Given Name`, `First Name` and ~40 other cases. Negative cases (referrer email, company name, "please state…"). Kind restrictions. Individual and combined confidence. |
| `core.test.ts` | Normalization (`India`/`india`/`INDIA`), keyword boundaries, scoring, profile defaults/merging, value resolution (salary opt-in), selection rules, validation, completion. |
| `option-matcher.test.ts` | Select matching by text, value, alias and contained words. Ambiguity refusal, placeholders, experience ranges, yes/no options. |
| `profile-store.test.ts` | save / load / update / clear, resume storage, change notifications (in-memory `chrome.storage` fake). |
| `field-detector.test.ts` | Ignored control types, label sources, nearby text, radio grouping, deduplicated incremental registry, pruning, shadow DOM. |
| `field-filler.test.tsx` | Filling input, textarea, select, checkbox and radio. Events fired. Failure isolation. Resume attach. **Real React controlled components** (and proof that a naive `el.value =` does not update React state). |
| `content-script.test.ts` | Content-script API, MutationObserver pickup of dynamically inserted fields, re-injection guard. |

### Manual test checklist

For each site (Greenhouse, Lever, Workday, Ashby, LinkedIn Easy Apply, Indeed, a generic careers page):

1. Open an application and click Fill2Fast. Check that the detected and matched counts look right.
2. Check that confident fields are pre-selected and that salary, unknown and low-confidence fields are not.
3. Click a field name. The page scrolls to that field and outlines it.
4. Deselect one field, click **Fill Selected**, and check that the page values are set and that the site's own validation accepts them.
5. Refresh and repeat. Edit your profile, reopen the popup, and check that the new value is used.
6. Turn off the network (DevTools → Offline) and check that everything still works.

## 8. Suggested V1.1 improvements

- Support common custom dropdowns (ARIA `listbox` / `combobox` patterns) generically: open, pick the matching option, verify.
- Per-country work authorization and sponsorship answers, picked by the country named in the question.
- A saved-answers library for recurring free-text questions (cover-letter snippets, "why us"), always opt-in per field.
- Multiple profiles (for example an Android profile and a Flutter profile) and multiple resumes.
- Remember per-site corrections (the field was X, not Y) locally to improve future matches on that site.
- Keyboard shortcut to open Fill2Fast and fill.
- Export and import the profile as JSON for backup.
- Structured education and work history (several entries) for forms that ask for them.
